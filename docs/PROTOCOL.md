# 比较与评分协议 v0.3.0

## 测什么

公开开发集包含基础组20题（原五类各4题）、研究挑战组4题和数据库工程应用组8题。三个赛道分别计分，未定义混合总分。测试工程agent的任务完成能力；不据此推断通用智力排名、材料真实性能、有限元求解器精度或生产安全认证。使用同一题目、输入、工具可达性和预算比较系统，而不是让一组使用私有答案库。

当前开发对照采用普通助手 + GPT-6.1 Sol high 与 ATLAS + 同一 GPT-6.1 Sol high。正式协议要求两组同样能调用基础建模、读写、计算和检索工具。模型ID、实际reasoning effort、速度模式、提示词hash、工具schema、依赖与数据版本必须记录并在正式运行前核实；配置名写着high不算验证。普通助手使用最小任务指令，不人为禁止工具；ATLAS只增加其工程指令与工作流程。如果ATLAS拥有独占工具，应另列“系统集成”赛道，不能把差异全归因提示词。

原版产品界面也是可选体验对照，但工具、系统提示及运行器不同，必须单列，不能混入主对照。已有外部5题诊断试跑，不构成32题完整评分；其固定题目、原始失败、成本和结果不随扩题改写。新增工程赛道尚未启动模型调用，正式预算须另行冻结。

## 每题如何发

1. 两组各建立新会话与干净工作目录，禁止读取其他案例答案、评分文件和历史聊天。
2. `export_case.py`默认只导出第一轮，可直接发给被测模型，包含当前`prompt_zh`、`inputs`、交付要求与来源卡。单轮题同时给数值schema，多轮题最终轮才给最终数值schema。
3. 多轮题用`--turn 2`/`--turn 3`严格依次导出并发送，每次等上一轮完成或触及预算。后续题包只给本轮修改量，不重述全部继承状态。不要将包含全部`followup_turns`的原始case对象交给模型。两组相同回复脚本，不因某组表现额外提示答案。固定后续轮次不算多余追问。
4. 基础数据和来源卡均随题给出。是否允许实时联网、哪些计算/CAD工具及版本必须对两组一致。来源卡不是论文复现实验；取不到全文不罚强行引用页码的替代能力。
5. 关键参数已知时不重复询问。预设故障题按输入事件做离线推演，不需要连接虚构服务器；CAD题要求真实交付，不能用离线推演代替。明确没有某项能力时如实报告并计交付未完成。
6. 每次保存原始聊天、工具调用、产物SHA256、实际模型/effort、时延、usage及人工介入。未经允许不能查看参考答案补写产物后还保留原分。

API模式按服务返回的输入/缓存/输出/推理用量记录真实费用；订阅模式不能把API价格当套餐扣量。若费用缺失，则效率费用分标“未测”，不当免费或满分。只报告可评的分项，不凑一个完整100分。该题库的离线脚本不调用模型，也不需要API凭据。

## 评分

四项质量维度：C工程准确性35、E证据20、D交付25、U省心10。`rubrics.json`每维内部points之和100。**每个检查是0或1，不使用临场半分**；多子条件检查须全部满足，遗漏写进review_notes。维度分为Σ(points×pass)/100。数值校验是C的部分证据，不能替代C/E/D/U的其他检查。缺少模型产物或检查记录不能预填通过。诚实未完成可获得已满足的其他检查分，并非失败的检查自动给半分。权重由本项目设定，不属于ISO/ASTM或外部benchmark的公认分值。

效率10分仅在C≥0.8、E≥0.8、D=1、无致命错误时可得：

`efficiency = 5*min(1,time_reference/elapsed_seconds) + 5*min(1,cost_reference/actual_cost)`。

time_reference和cost_reference须按类别用独立试跑事前确定并冻结；同类两组共用，不可看最终结果再调。缺失或不可比成本时不发布完整100分，单列质量分/90和耗时、用量。零成本、零时延、负数或未知值必须审查来源，不能通过除零得到满分。

完整分：`35*C+20*E+25*D+10*U+efficiency`。每题列出的致命错误触发时该次总分0，保留分项诊断和原始输出。必要澄清不扣分，关键条件瞎猜会影响准确性。Markdown外观、答案长度、与参考措辞相似度不作为得分依据。

先用工具做计算、文件重读、拓扑及测量，再由隐藏组名的人审处理语义/证据；不能由被测模型自报分数。盲化组名不能保证审阅人完全猜不出系统，需要披露。评审分歧要记录，修改rubric时版本化并同时重评两组。

## 结果汇总与预算

第一步可用5题（每类一题）×两组各一次进行可行性/用量试跑。具体选择在运行前冻结，不能为争取好看比分只挑易题。每次最大总输入/输出token、墙钟、模型调用、工具调用和重试上限对两组相同；high推理token计入相应服务输出用量，不额外漏算。参考协议尚未给出未经试跑的强制数值预算。

正式可复现公开对照若采用20题×两组×3次，共120个任务运行，不是120个API请求。随机交错执行两组，记录失败和超时；自身恢复失败不能悄悄删掉。只按预先登记的外部共同故障规则成对重跑，保留原失败。

每题先平均3次得分，再比较差值：ATLAS高于基线超过3分为胜，低于超过3分为负，差值绝对值≤3分为平。五个类别均值等权汇总；报告分项、完整交付率、致命错误率、时间和用量。bootstrap以题目为配对单位，重复运行不算新的独立题；20题仍不足支持广泛泛化声明。

## 公开集与保留集

本次发布的32题及答案都是public_development。它们可用于逐指标优化，并公布真实公开集比分。**公开后在这些题上调优，再把同题称“最终盲测”不成立。**

最终未见题评测需由独立保管方另建题目、oracle和rubric并冻结hash。按结构族、几何模板和同源实验trial分组，不能仅改一个参数就当独立测试。开发者只看必要汇总；查看答案后，该保留集退役为回归集。现阶段没有创建或执行这套保留集。

## 研究挑战的独立验收

LAT-21—24形成独立赛道，四题等权；每题先平均重复运行，再汇总。若做每组3次，新增24个任务运行，与基础组120次分别报告。没有预注册新的聚合权重前，不把144次混成“新版总分”。

四题的累计试跑预算暂定为每组每题3600秒、16次模型调用、80次工具调用、25万输入token、6万输出token（含推理）。这些是上限，不是预计消耗；仍须试跑校准并在正式运行前冻结。几何设计最多12个候选；LAT-22更严格为8个设计、每步200迭代、每迭代40线搜索试探；LAT-24修复候选最多3个。失败和重试仍计预算。独立细化复核可按题设豁免“新设计”计数，但不豁免累计时间、工具或模型用量。

环境在两组间一致且事前记录：Python/数值库、CAD内核、布尔及网格工具、CPU/内存、线程数、求解器版本。若环境不能执行必须检查的功能，题目只能作为能力缺口诊断，不得用假产物补齐成功记录；需要换环境时两组一起重跑并保留原记录。

- LAT-21的几何目标只做过解析预算检查，完整几何可行性未由参考CAD实测。先试跑验证约束可实现性及特征检测方法；若题目存在不可判定或不合理条件，版本化修正并同步重评双方。
- LAT-22已有作者端数值可行性探查，但没有完整CAD交付成绩。计分需重新运行被测者源文件与独立细步长验证；作者探查不计被测模型成绩。
- LAT-23的无解仅限题设拓扑、密度与合成代理。实际改型还要通过布尔并集、体积误差与代理区间检查，不能用解析参考半径代替STL。
- LAT-24附带哈希固定的损坏输入；不能给被测者干净参考网格、重建配方或全部仓库。完整成功必须包含自交/表面/孔道检查，`mesh_audit.py`的离散拓扑检查只是部分证据。

上述阈值均为本题库合同；正式实验应选择适用的外部方法标准，见[已有标准与基准](STANDARDS.md)。本项目没有声称通过ISO/ASTM全条款符合性审查。

## 数据库工程应用的独立验收

这组题以完成工程决策为目标：数值估算、约束判定、定量行动建议和证据追溯应一起交付。尚缺局部FE证据时，仍须完成现有数据支持的整体估算；仅陈述风险或未知项，不计为有用交付。

LAT-32的N5实验必须顺序隔离，不只隐藏附件：控制器在两组所有轮次关闭网络、原始数据库与答案仓库访问；ATLAS领域工具仅允许不读取实验结果的 `physical_checks`、`lattice_build`，其余数据库检索工具从实际可调用列表移除。第一轮结果及预测哈希冻结后才释放N5附件。无法落实这些控制就停止该题正式计分。现有五题smoke运行器尚未实现此新控制，也没有启动LAT-32；公开的顺序留出不能宣称秘密盲测。

LAT-25—32组成8题工程应用赛道，先按每题平均重复运行，再对8题等权汇总。每组3次将增加48个任务运行，分别报告于基础组120次和挑战组24次；没有预先登记的混合权重，不合成“192次新版总分”。新增题目不修改已有5题烟雾试跑计划，也不因保存题库而启动付费调用。

两组从同一份SHA256固定的精简ATLAS快照读取相同记录，获得相同当前轮附件；基线可用通用读写与计算工具自行检索和复算。ATLAS可使用经过验证的数据库/物理工具，但工具可达性差异必须如实登记为系统集成比较。来源ID、完整上游manifest哈希、精简快照哈希、记录ID及曲线/实验附件哈希写入证据记录。工具返回成功不是性能已经实证，不能预设ATLAS获胜。

工程场景是合成输入。附件按provenance区分直接仿真、N5扩展估算、真实实验及合成反馈；`inputs.synthetic=false`只表示不能将整包统称为合成数据。N5扩展记录不是新增独立FEA或实验次数，缺失密度、局部应力、材料/几何参数时保持缺失。若实验cohort没有slider、radius或材料追溯，只能按题设范围比较cohort曲线代理，不得声称已对指定型号或任意材料完成实验验证。

受力估计必须报告面积与高度、载荷方向、边界条件、单位以及所用均匀化/串并联等假设；名义力除以包络面积不能替代局部杆件应力。数据库的0.5%偏移屈服是该题采用的整体应力—应变曲线指标，既不等于局部首屈服，也不证明局部塑性位置。没有局部场或与材料、工艺匹配的验证证据时，应给出待验证项及下一步测量/求解计划。超出标定范围的性能应标注为估算，不作为可靠工程PASS。

多轮反馈必须按固定轮次释放。独立的后续轮附件只在`available_from_turn`到达时导出；首轮不能含后续观测值、后验校准系数或它们对应的最终输出schema。实际实验应按其来源称为实验，合成反馈不能改称实测。两组收到相同反馈脚本，不因表现不同额外提示。

数值oracle只检查题设假设内可重算的锚点。完整交付还需要证据追溯、载荷与屈服定义、估算边界、反馈后可审查的判断和题目要求的产物。新增题预算是试跑提案，正式模型比较前冻结并同时应用；目前没有新增赛道成绩。
